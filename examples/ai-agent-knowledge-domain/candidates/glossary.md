## g01 LLM Agent
- **类型**: glossary
- **来源**: 10 Ch1 (Ch1 核心定义); 12 Ch1; 02 Intro; 01 Ch1
- **chain_level**: L0
- **作者用法**: 自主系统 = **backbone LLM + tools + processing loop**。Fajardo 给出最严格定义:"An LLM agent is an autonomous system, comprised of a backbone LLM and tools, that acts on tool-call requests generated by the LLM"。
- **通用含义**: "智能体" — 与"chatbot"混用,**LLM agent 强调自主决策+工具调用,chatbot 仅响应**。
- **易混淆术语**: Traditional AI Agent (规则驱动,Wooldridge); Reinforcement Learning Agent (学习范式); Chatbot (纯对话)
- **原文关键句**: "An LLM agent is an autonomous system, comprised of a backbone LLM and tools, that acts on tool-call requests generated by the LLM to perform tasks." (10 Ch1)

## g02 Agentic Design Pattern
- **类型**: glossary
- **来源**: 02 全书 (21 个模式专章); 12 Ch2
- **chain_level**: L1
- **作者用法**: Gulli 提出 21 个可复用模式,包括 Prompt Chaining / Routing / Reflection / Tool Use / Planning / Multi-Agent / Memory / Learning / MCP / Goal / Exception / HITL / RAG / A2A / Resource-Aware / Reasoning / Guardrails / Evaluation / Prioritization / Exploration。
- **通用含义**: "设计模式" — 与软件设计模式混用,**agentic patterns 专为 LLM 智能体场景设计**。
- **易混淆术语**: Software Design Patterns (Gang of Four); Architecture Patterns; Anti-Patterns
- **原文关键句**: "This book extracts 21 key design patterns that represent fundamental building blocks and techniques for constructing sophisticated agents." (02 Intro)

## g03 ReAct (Reason + Act)
- **类型**: glossary
- **来源**: 02 Ch17 (专章); 05 Ch4 (ReAct Agents 段); 07 Ch1 (航班示例); 10 Ch1 (Planning vs CoT)
- **chain_level**: L1
- **作者用法**: Yao 等 2022 提出的范式,**将 Chain-of-Thought 推理与工具调用交错进行**,循环为 Thought → Action → Observation → Thought...。
- **通用含义**: "推理+行动" — 易与"思维链"混用,**CoT 是纯推理,ReAct 必含动作**。
- **易混淆术语**: Chain-of-Thought (纯推理无动作); Self-Reflection (反思扩展); Tool Use (动作本身)
- **原文关键句**: "ReAct operates in an interleaved manner: the agent executes an action, observes the outcome, and incorporates this observation into subsequent reasoning." (02 Ch17)

## g04 Reflection / Reflexion
- **类型**: glossary
- **来源**: 02 Ch4 (专章); 05 Ch4 (Reflection Agents); 07 Ch4 (反思与内省)
- **chain_level**: L1
- **作者用法**: Shinn 等 2023 提出的自我反思模式,agent 在每轮后生成 critique → 强化反思 → 重试。**ReAct 是基础循环,Reflexion 是其上叠加的反思层**。
- **通用含义**: "反思" — 不等同于"复盘",**Reflexion 是带语言化强化信号(verbal RL)的特定模式**。
- **易混淆术语**: Meta-Reasoning (更宽概念); Self-Correction; Self-Refine; Chain-of-Thought (无反思)
- **原文关键句**: "Reflection and metareasoning agents extend the ReAct paradigm by not only interleaving thought and action but also adding a self-critique step." (05 Ch4)

## g05 MCP (Model Context Protocol)
- **类型**: glossary
- **来源**: 02 Ch10 (专章); 05 Ch6 (USB-C 比喻); 11 Ch2; 12 Ch12; 10 Ch5; 07 推荐序
- **chain_level**: L2
- **作者用法**: Anthropic 2024 推出的开放标准,**LLM 与外部工具/数据源之间的标准化接口**(类 USB-C),基于 client-server 架构,通过 JSON-RPC 2.0 通信。Server 暴露 tools/resources/prompts 三类原语,Client 动态发现并调用。
- **通用含义**: "模型上下文协议" — 日常常被误读为"提示词协议",**严格定义是工具/资源发现传输协议**。
- **易混淆术语**: A2A (关注智能体间通信); Function Calling (厂商私有); OpenAPI (传统 REST)
- **原文关键句**: "MCP operates on a client-server architecture. Resources and actionable functions (known as tools) are exposed by an MCP server. These are then consumed by an MCP client, which could be an LLM host application or an AI agent itself." (02 Ch10)

## g06 A2A (Agent-to-Agent)
- **类型**: glossary
- **来源**: 02 Ch15 (专章); 10 Ch1; 12 Ch12.3 (与 MCP 对比)
- **chain_level**: L2
- **作者用法**: Google 发起的开放标准,**用于跨组织/跨框架的智能体间通信**,基于 HTTP 端点,核心概念:Agent Card (能力自描述)、Task lifecycle state、contextId;支持异步轮询、SSE/WebHook 流式更新。
- **通用含义**: 与 MCP 易混,**A2A 关注智能体作为对等实体协作,MCP 关注智能体使用工具**。
- **易混淆术语**: MCP (工具协议); KQML/FIPA ACL (学术历史); gRPC/REST (通用 RPC)
- **原文关键句**: "A2A is a protocol that complements Anthropic's Model Context Protocol (MCP). While MCP focuses on structuring context for agents and their interaction with external data and tools, A2A focuses on high-level coordination and task delegation between autonomous agents." (02 Ch15)

## g07 Agent Skills
- **类型**: glossary
- **来源**: 10 Ch6 (专章首次定义); 02 索引
- **chain_level**: L2
- **作者用法**: Anthropic 推出的开放标准,**定义可复用工作流(skills)的创建与发现方式**。Skill 由 SKILL.md (frontmatter + procedural workflow + 资源文件) 描述,session 启动时 agent 激活并加载到上下文。
- **通用含义**: "智能体技能" — 与"提示词模板"混用,**Skills 是带结构化 frontmatter 的程序化工作流文档**。
- **易混淆术语**: Prompt Template (无 frontmatter); MCP Tools (函数式); LangChain Tools (框架私有)
- **原文关键句**: "The Agent Skills open standard provides a way to bundle everything an LLM agent needs to perform a task in a documented workflow. Unlike skills, MCP tools are discovered once at the creation time of an LLMAgent." (10 Ch6)

## g08 Orchestrator
- **类型**: glossary
- **来源**: 12 Ch7 (orchestrator-specialist); 05 Ch5 (orchestration strategies); 11 Ch6 (orchestration layer); 02 Ch7
- **chain_level**: L1
- **作者用法**: 智能体系统中央协调者,**负责任务分解、子任务分发、状态管理**。在 12 中分为两类:orchestrator-specialist (中央调度多个专家) 与 peer coordination (对等委托)。**与 workflow engine 区别:orchestrator 使用 AI 推理做路由,而非预定义规则**。
- **通用含义**: "编排者" — 与"调度器(scheduler)"混用,**orchestrator 含语义推理,scheduler 多为预定规则**。
- **易混淆术语**: Workflow Engine (Airflow/Step Functions); Router (Ch2 模式); Supervisor Agent; Manager (Contract Net)
- **原文关键句**: "Agent orchestrators do the same but use AI-driven reasoning to decompose complex requests, route to specialist agents, and coordinate execution." (12 Ch7)

## g09 CWD (Coordinator-Worker-Delegator)
- **类型**: glossary
- **来源**: 07 Ch6 (专章定义); 08 Ch7
- **chain_level**: L1
- **作者用法**: 多智能体协作设计模式。**Coordinator** 负责顶层任务分解与监督;**Worker** 执行具体子任务;**Delegator** 把超出自身能力的子任务转包。书中以旅行预订系统为例。
- **通用含义**: 与"主从架构(master/slave)"不同,**CWD 三种角色可重叠且具有协商性**。
- **易混淆术语**: Orchestrator-Worker (LangGraph,术语异); Supervisor Agent; Manager-Worker (Contract Net)
- **原文关键句**: "本章介绍了多智能体协作中的 CWD 模型,解释了智能体如何承担协调者、工作者或委派者等角色,以优化任务执行和资源分配。" (07 Ch6 目录)

## g10 Workflow vs Autonomous
- **类型**: glossary
- **来源**: 12 Ch2; 05 Ch1; 02 Ch6
- **chain_level**: L0
- **作者用法**: **Workflow** = 确定性计算图(预定义节点+边);**Autonomous** = 涌现编排(LLM 推理决策路由)。Dibia 明确二者区别:workflow 适合可枚举决策分支场景,autonomous 适合高变异、开放式推理。
- **通用含义**: "工作流/自主" 混用,**workflow 强调可预测性,autonomous 强调适应性**。
- **易混淆术语**: Pipeline (数据流,非控制流); RPA (规则驱动自动化); Agentic Workflow (有 AI 决策的工作流,中间态)
- **原文关键句**: "Workflows are deterministic graphs; autonomous systems are emergent. The complexity of a decision tree drives the planning strategy you are likely to need." (12 Ch2, 05 Ch5)

## g11 Context Engineering
- **类型**: glossary
- **来源**: 11 Ch1-5 (全书主题); 05 Ch4; 07 Ch7 (聚焦式指令)
- **chain_level**: L0
- **作者用法**: Rothman 明确:**将生成式 AI 转化为可靠、目标导向系统的学科**,实践包括五级进阶(基本提示 → 更好上下文 → 目标导向 → 链式上下文 → 语义蓝图)。**不是写"更好的 prompt",而是结构化、管理、治理 AI 上下文**。
- **通用含义**: "上下文工程" — 与 prompt engineering 混用,**范围更广,涵盖 prompt + memory + RAG + 蓝图 + 工作流**。
- **易混淆术语**: Prompt Engineering (仅提示层); Instruction Tuning (训练阶段); RAG (子集)
- **原文关键句**: "At its heart lies the emerging discipline of context engineering, the practice of structuring, managing, and governing the information provided to generative AI to transform it from a text generator into a reliable, goal-oriented system." (11 Ch1)

## g12 Semantic Blueprint + SRL
- **类型**: glossary
- **来源**: 11 Ch1 (首次定义); 11 Ch5 (专章)
- **chain_level**: L0
- **作者用法**: 通过 **Semantic Role Labeling (SRL)** (源自 Fillmore 格语法) 将自然语言提炼为"谁做了什么对谁、何时、为何"的语义角色,**最终产物是 JSON 格式结构化指令(语义蓝图)**,比 prompt 更精确,比 schema 更灵活。
- **通用含义**: "语义蓝图" — 与"模板(template)"混用,**blueprint 是带语义角色标注的结构化执行计划**。
- **易混淆术语**: Prompt Template (无语义角色); JSON Schema (无语义内涵); Tool Spec (工具描述)
- **原文关键句**: "A semantic blueprint is a structured, unambiguous plan provided to the LLM, typically in JSON format. By using semantic blueprints, we provide the LLM with a precise schema rather than an open-ended request." (11 Ch5)

## g13 Glass-Box Context Engine
- **类型**: glossary
- **来源**: 11 Ch4,6,10 (全书中枢)
- **chain_level**: L0
- **作者用法**: 与"黑箱"对立的设计原则,**agent 系统的每一步决策、检索、生成都可追溯、可审计、可视化**。三支柱:**ExecutionTrace (不可变追踪) + Centralized Logging (集中日志) + Observability Stack (可观测性栈)**。
- **通用含义**: "玻璃箱" — 与"开源"混用,**glass-box 是运行时可观测性,与代码是否开源无关**。
- **易混淆术语**: Black-Box (对立); Open Source (代码层); Explainable AI (XAI,模型层); Interpretability
- **原文关键句**: "Transparency is the defining feature of a glass-box system. This capability, known collectively as observability, is what distinguishes a prototype that merely works from a system that is auditable, debuggable, and trustworthy." (11 Ch6)

## g14 Dual RAG
- **类型**: glossary
- **来源**: 11 Ch3 (首次定义架构); 05 Ch6
- **chain_level**: L0
- **作者用法**: Rothman 多智能体 RAG 架构,**同时维护两个向量检索源**:(1) Knowledge Base 存事实数据;(2) Context Library 存过程性指令(语义蓝图)。运行时 Librarian agent 检索 intent → 调出对应 blueprint → 配合 facts 生成输出。
- **通用含义**: "双 RAG" — 与传统单 RAG 相比,**dual RAG 显式区分"是什么"与"怎么做"**。
- **易混淆术语**: Single RAG (仅事实); Agentic RAG (10 Ch1,agent 增强 RAG); GraphRAG (知识图谱); High-Fidelity RAG (11 Ch7)
- **原文关键句**: "The dual RAG MAS architecture... separates factual knowledge (knowledge base) from procedural instructions (context library)." (11 Ch3)

## g15 High-Fidelity RAG
- **类型**: glossary
- **来源**: 11 Ch7; 05 Ch6
- **chain_level**: L0
- **作者用法**: **每条事实附带 source citation** 的 RAG,使输出可溯源验证,降低幻觉风险。Rothman 强调 citation 是 RAG 高保真的关键。
- **通用含义**: "高保真 RAG" — 与普通 RAG 区别在于**是否带引用溯源**。
- **易混淆术语**: Regular RAG (无引用); GraphRAG (图结构); Self-RAG (自我评估的 RAG)
- **原文关键句**: (11 Ch7 强调"each fact must be attached with source citation to ensure fidelity")

## g16 BDI (Belief-Desire-Intention)
- **类型**: glossary
- **来源**: 03 Ch4 (专章详尽定义); 04 Ch4; 12 Ch2 (慎思型架构)
- **chain_level**: L3
- **作者用法**: Bratman 等 1988 提出的实用推理模型。智能体持有**信念 (Belief,关于世界) / 愿望 (Desire,目标状态) / 意图 (Intention,已承诺执行的计划)**。最著名实现是 PRS (Procedural Reasoning System, Georgeff)。BDI 强调**意图的承诺性与重审议平衡**。
- **通用含义**: "信念-愿望-意图" — 不等同于简单目标管理,**关键在意图的承诺性(committed)与持续推理的张力**。
- **易混淆术语**: Intentional System (Dennett,哲学); Goal-Oriented Planning (无承诺); HTN Planning (BDI 子技术)
- **原文关键句**: "An illustration of the PRS architecture is given in Figure 4.4. The PRS is often referred to as a BDI system... The conceptual framework of the BDI model is described in Bratman et al., 1988." (03 Ch4)

## g17 Contract Net
- **类型**: glossary
- **来源**: 03 Ch8.2 (专节定义); 04 Ch8; 12
- **chain_level**: L3
- **作者用法**: Smith 1980 提出的任务分配协议:**manager 广播 task announcement → 潜在 contractor 投标 → manager 评标并授标**。三类消息:task announcement / bid / award。"被实现最多、研究最深入"的多智能体协议。
- **通用含义**: "合同网" — 不等同于"招标",**强调迭代多轮投标-中标流程与 manager 单点决策**。
- **易混淆术语**: Auction (机制设计视角); English Auction / VCG; Negotiation (更广)
- **原文关键句**: "The Contract Net has become the most implemented and best-studied protocol for task sharing in multiagent systems." (03 Ch8)

## g18 MemGPT
- **类型**: glossary
- **来源**: 08 Ch5; 02 Ch8 (Memory Management 提及); 05 Ch6 (semantic memory 区分)
- **chain_level**: L0
- **作者用法**: 受操作系统虚拟内存启发,**显式区分 short-term / long-term memory**:短期存于上下文窗口,长期存于外部存储,通过分层读写机制扩展 agent 记忆容量。**关键创新是 hierarchical memory management**。
- **通用含义**: 与"长上下文模型"混用,**MemGPT 强调主动记忆管理策略而非单纯扩大窗口**。
- **易混淆术语**: Long Context Window (技术上限); RAG (互补); Vector Memory (存储介质)
- **原文关键句**: (02 Ch8 与 05 Ch6 共同描述分层记忆;08 Ch5 在中文语境下讨论操作系统式虚拟内存管理)

## g19 Trajectory
- **类型**: glossary
- **来源**: 10 Ch4 (专章); 02 Ch19; 05
- **chain_level**: L0
- **作者用法**: agent 完成一次任务的**完整步骤序列**:包含每步计划、思考、工具调用、观察、最终答案。Fajardo 强调 trajectory 与 rollout 同义,**是评估 agent 行为的核心数据结构**。
- **通用含义**: "轨迹" — 不等同于"日志(log)",**trajectory 是结构化事件序列,可被 replay 与评估**。
- **易混淆术语**: Trace (技术调试日志); Log (通用文本); Session (按会话切分); ExecutionTrace (Rothman,同义)
- **原文关键句**: "The sequence of steps an agent takes from start to finish is often referred to as the LLM agent's trajectory or rollout. In a trajectory, you can see the plans and tool calls made in every step." (10 Ch1)

## g20 Trajectory-Based Evaluation
- **类型**: glossary
- **来源**: 12 Ch10; 02 Ch19; 05 Ch9
- **chain_level**: L4
- **作者用法**: **评估执行轨迹而非仅最终输出**。通过 replay 轨迹找失败步骤,优于只看结果的端到端评估。Gulli 明确 agent trajectories 是"crucial for evaluation"。
- **通用含义**: "轨迹评估" — 与 end-to-end 评估混用,**前者看过程,后者看结果**。
- **易混淆术语**: End-to-End Evaluation (只看结果); Outcome Testing; Step-level Evaluation
- **原文关键句**: "Agent trajectories, the sequence of steps an agent takes, are crucial for evaluation, comparing actual actions against expected behavior at each step." (02 Ch19)

## g21 Agentic Noise
- **类型**: glossary
- **来源**: 12 Ch13; 05 Ch10
- **chain_level**: L4
- **作者用法**: 大规模 agent 部署的**累积性干扰/风险**:单个 agent 输出的随机性 + 多个 agent 协作时的信号累积偏差 + prompt injection 风险叠加。**这是大规模生产环境特有的现象,非单元 agent 关注**。
- **通用含义**: "智能体噪声" — 与 LLM hallucination 混用,**noise 是统计波动,hallucination 是事实错误**。
- **易混淆术语**: Hallucination (事实错误); Stochastic (随机性数学术语); Temperature Effect
- **原文关键句**: "Agentic noise is the cumulative interference of many agents operating at scale, distinct from individual hallucination." (12 Ch13)

## g22 Rule of Two
- **类型**: glossary
- **来源**: 12 Ch13; 02 Ch18 (隐含); 11 Ch9
- **chain_level**: L4
- **作者用法**: AI 智能体部署风险原则:**同时满足任意两条**特性即需特别警惕:(1) 接受不可信输入;(2) 处理不可信内容;(3) 与外部世界通信并改变状态;(4) 访问敏感数据源。Dibia 将其作为 HITL 与 guardrail 设计的触发器。
- **通用含义**: 与"零信任"混用,**Rule of Two 是触发器而非完整安全模型**。
- **易混淆术语**: Zero Trust (整体安全架构); Defense in Depth; Principle of Least Privilege
- **原文关键句**: "Rule of Two: an agent with any two of {untrusted input, untrusted content, external state change, sensitive data access} must have explicit guardrails." (12 Ch13)

## g23 Prompt Injection
- **类型**: glossary
- **来源**: 11 Ch7 (详尽); 02 Ch18; 05 Ch5; 12 Ch13
- **chain_level**: L4
- **作者用法**: 通过输入(直接 prompt 或 RAG 检索文档)中嵌入恶意指令,使 LLM 偏离原始任务。**两阶段攻击**:(1) data poisoning 注入向量库;(2) 检索时 prompt injection 劫持行为。
- **通用含义**: 与"jailbreak"混用,**prompt injection 强调注入恶意指令,jailbreak 强调绕过安全对齐**。
- **易混淆术语**: Jailbreak (绕过对齐); Data Poisoning (污染数据); Social Engineering (针对人); Indirect Prompt Injection (通过检索)
- **原文关键句**: "Data poisoning is the act of inserting malicious text into the knowledge base, which can later cause a prompt injection attack when that data is retrieved by an agent." (11 Ch7)

## g24 Data Poisoning
- **类型**: glossary
- **来源**: 11 Ch7; 02 Ch18; 05 Ch5
- **chain_level**: L4
- **作者用法**: 在训练数据、知识库或 RAG 检索源中插入恶意内容,使 agent 在后续查询中触发有害行为。**通常作为 prompt injection 的第一阶段**(两阶段攻击)。
- **通用含义**: "数据投毒" — 不等同于"模型中毒",**poisoning 可作用于训练阶段或检索阶段**。
- **易混淆术语**: Backdoor Attack (训练后门); Model Poisoning (仅训练阶段); Adversarial Example (输入扰动)
- **原文关键句**: "Stage 1: An attacker first manages to get malicious text into the vector database, called data poisoning. Stage 2: When the agent retrieves this poisoned content, the hidden instructions hijack the LLM's behavior." (11 Ch7)

## g25 Guardrails
- **类型**: glossary
- **来源**: 02 Ch18 (专章); 11 Ch7; 12 Ch13; 05 Ch12
- **chain_level**: L4
- **作者用法**: 智能体安全模式的总称,**多层防御策略**:Input Validation / Sanitization (过滤恶意输入)、Output Filtering / Post-processing (毒性/偏见过滤)、Behavioral Constraints (提示词层约束)、Tool Use Restrictions、HITL。**关键不是限制 agent 能力,而是确保稳健可信赖**。

- **易混淆术语**: Content Moderation (仅输出层); Prompt Filter (仅输入层); Jailbreak Detection (单一攻击类型); Safety Filter

## g26 Nash Equilibrium
- **类型**: glossary
- **来源**: 03 Ch11.3 (核心定义); 04 Ch11; 06 Ch8
- **chain_level**: L3
- **作者用法**: 在多人博弈中,若每个参与者在其他参与者策略固定时都选择了自己的最优反应,这些策略的组合即为 Nash 均衡。Nash 1950 证明每个有限策略博弈都存在混合策略均衡。**计算混合策略 NE 是 PPAD 完全问题**。
- **通用含义**: "纳什均衡" — 日常用法常忽略**纯策略 NE 不一定存在(经典例子:Matching Pennies),且可能存在多个**。
- **易混淆术语**: Pareto Efficiency (效率,不要求均衡); Dominant Strategy Equilibrium (更强); Correlated Equilibrium (不同概念)
- **原文关键句**: "Two strategies s1 and s2 are in Nash equilibrium if: under the assumption that agent i plays s1, agent j can do no better than play s2... Every game in which every player has a finite set of possible strategies has a Nash equilibrium in mixed strategies." (03 Ch11)

## g27 Shapley Value
- **类型**: glossary
- **来源**: 03 Ch13.1.2 (专节); 04 Ch13
- **chain_level**: L3
- **作者用法**: Lloyd Shapley 提出的合作博弈公平分配解,基于三个公理(Symmetry / Dummy Player / Aditivity),**定义每个 agent 获得其对所有可能联盟的平均边际贡献**(Eq 13.2)。**Shapley 证明任何满足这三个公理的值就是 Shapley 值本身**。
- **通用含义**: "夏普利值" — 不等同于"平均分配",**而是按平均边际贡献分配,且满足唯一性定理**。
- **易混淆术语**: Banzhaf Index (不同公理); Core (集合概念); Nucleolus (其他公平解)
- **原文关键句**: "Shapley's idea was that an agent should get the average marginal contribution it makes to a coalition... Shapley proved that if the value you define satisfies the fairness axioms given above, then your value is the Shapley value as defined in Equation 13.2!" (03 Ch13)

## g28 VCG Mechanism (Vickrey-Clarke-Groves)
- **类型**: glossary
- **来源**: 03 Ch14.3.3 (专节); 04 Ch14
- **chain_level**: L3
- **作者用法**: 满足**激励兼容**(incentive-compatible/truthful)的拍卖/机制设计机制,出价最高者获得物品,但支付额 = 第二高价 + 损害其他参与者的机会成本 (Clark tax / Groves tax)。**关键性质:真实报价是占优策略**。
- **通用含义**: "VCG 机制" — 不等同于"英式拍卖",**VCG 是抽象机制设计框架,具体到单物品就是 Vickrey (second-price) auction**。
- **易混淆术语**: Vickrey Auction (VCG 单物品特例); First-Price Auction (不满足真实性); Combinative Auction
- **原文关键句**: "The VCG mechanism... a generalization of the Vickrey auction to multi-item and combinatorial settings, with the property that truthful bidding is a dominant strategy." (03 Ch14)

## g29 Intentional System
- **类型**: glossary
- **来源**: 03 Ch2-3 (Dennett 引述); 04 Ch2
- **chain_level**: L3
- **作者用法**: Dennett 提出的意向立场(intentional stance)概念,**一阶意向系统有 B/D/I 但无 B/D/I about B/D/I;二阶意向系统则对自己的意向也有意向**。用 B/D/I 解释智能体行为的哲学基础。
- **通用含义**: "意向系统" — 与"有意识系统"不同,**意向性是预测/解释工具,不蕴含意识或真实心智状态**。

- **原文关键句**: "A first-order intentional system has beliefs and desires (etc.) but no beliefs and desires about beliefs and desires... A second-order intentional system is more sophisticated; it has beliefs and desires about beliefs and desires." (03 Ch2-3)
