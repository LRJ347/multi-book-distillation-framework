# 04 — 阶段 3:三重筛选 + MB 来源独立(DISTILL)

## 目标

从候选池筛出**真正值得做成独立 skill 的方法论单元**。通不过的降级为 example/引用/术语,不独立成 skill。这是本框架区别于"书摘工具"的核心质量门。

## 验证项(全部通过才录取)

### V1 — 证据独立性(Evidence Independence)
- **问题**: 至少 2 个**独立证据场景**佐证?(同书不同章节/不同案例,不是同一案例换说法)
- 通过示例: 某方法在投资决策、工程设计、教学三个独立场景都出现 → 通过
- 不通过示例: 漂亮句子只在某章出现一次 → 降级为金句 example

### V2 — 预测力(Predictive Power)
- **问题**: 能用它回答书里没明说的新问题吗?
- 通过: 设计书未讨论的新场景,用该方法论能得出有意义、非平庸结论
- 不通过: 只能得出"努力就会成功"之类的废话 → 无解释力,降级
- **baseline 对照**(防常识包装): 不给 skill 仅用通用知识的 B 组若得到相似答案 → 该单元是常识重包装,判 V2 不通过(与 V3 联动)

### V3 — 独特性(Exclusivity)
- **问题**: 是任何聪明人都会说的常识吗?
- 通过: 作者独特视角/反直觉见解/独特术语体系(如"stop doing list"主动列不做什么)
- 不通过: "要尊重时间"这类常识 → 不需要 skill 承载

### MB — 来源独立性(Source Independence)
- **问题**: 至少 2 条**独立证据链**吗?(见 EVALUATION_PROTOCOL.md §1)
- 硬门槛: independent_chain_count ≥ 2(不同作者、非传播链)
- 质量门: 至少 1 条链达到 L3/L4
- 注意: 5 本书引用同一源头 = 1 条证据链 × 5 次传播,不算多书交叉

## 执行流程

1. 合并 5 个 candidates/*.md 为总候选池
2. 去重(同一方法论被多 extractor 提取的合并)
3. 逐条跑 V1/V2/V3/MB,记录判断和理由
4. 通过 → verified.md,进入阶段 4
5. 未通过 → rejected/<id>.md(必须写明哪项不通过 + 原因,保留审计轨迹)

## verified.md 单条格式

```yaml
id: f01
title: <标题>
type: <类型>
V1_evidence: { passed: true, evidence: [<书1 第X章>, <书1 第Y章>] }
V2_predictive: { passed: true, novel_question: "...", derived_answer: "...", baseline_diff: "显著优于常识基线" }
V3_exclusive: { passed: true, why_not_common: "..." }
MB_source: { independent_chains: 2, chain_levels: [L4, L3], sources: [<书A>, <书C>] }
→ 进入阶段 4
```

## 常见失败模式

1. **V1 作弊**: 同一例子换说法算两处 → 必须不同章节 + 不同对象 + 不同结论
2. **V2 作弊**: 用书里讨论过的类似问题冒充新问题 → 新问题应让人第一眼不知道书里怎么说
3. **V3 过松**: 只要"说得文雅"就认为非常识 → 看内容是否反直觉,不看措辞

## 数量预期与诊断

- 方法论密集的书: 通过率约 30-50%;散文类 5-10%
- **DM-4 Calibration Warning**: 通过率 >80% 或 <5% → 警告(标准可能过松/过严),**不自动判失败**——不同领域知识密度差异巨大,仅要求重新检查标准

## 用户轻确认 ★

筛选完成后展示:"通过的 N 个候选 + 淘汰的 M 个",询问"有想捞回或砍掉的吗?"——阶段 4-8 最耗时,此确认避免大量返工。
