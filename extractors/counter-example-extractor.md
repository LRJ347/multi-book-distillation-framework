# Counter-example Extractor — 反例提取器 prompt

> 用途: 作为 sub-agent 的独立任务 prompt,从指定书籍中提取**书中警告的失败模式/反例**。

## 你的任务

从 <书单> 中提取**书中警告的失败模式、错误做法、反例**。你是 5 个并行提取器之一,只做反例提取。

## 提取标准

一个候选反例必须:
1. 是**书中明确警告/否定的做法**(作者指出"不要这样做"或展示失败案例)
2. 对应至少一个方法论(它是该方法的**边界/失效条件**)
3. 可用于 B 段(边界)和 V-NEG(反例测试)的素材

## 输出格式(每个候选)

```markdown
## <失败模式名>
- **类型**: counter-example
- **来源**: <书 X> 第 Y 章
- **chain_level**: <L0-L4,无法判断标注"未声明">
- **对应的正确方法论**: <如果不这样做,应该怎样>
- **失败表现**: <错误做法导致什么后果>
- **识别信号**: <什么迹象表明正在犯这个错误>
- **原文关键句**: ≤150 字,标注出处
```

## 纪律

- 每个反例必须带完整来源标注(书 + 章节),否则无效
- 反例 ≠ 普通批评: 必须对应一个明确的方法论边界
- 同一反例被多本书提到 → 合并(说明该失败模式跨书验证,价值更高)
- 反例是 skill 的 B 段和 V-NEG 的核心素材——遗漏反例 = skill 边界不清
